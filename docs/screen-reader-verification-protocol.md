# Протокол проверки Rovna UI экранным диктором

Обновлено: 2026-08-09.

Статус: ручной протокол подготовлен; фактическое прослушивание остается отдельной приемочной проверкой.

## 1. Назначение и граница автоматизации

Протокол проверяет то, что нельзя достоверно подтвердить axe, DOM-проверками и браузерными тестами: порядок и понятность речевых объявлений, отсутствие лишних повторов, своевременность live-region сообщений и удобство непрерывной работы без зрения.

Автоматические результаты R-04 подтверждают роли, имена, связи ARIA, клавиатурный фокус и отсутствие критических/серьезных нарушений. Они не являются сертификатом качества фактического синтезированного вывода.

Владелец исполнения: QA-инженер или сопровождающий дизайн-системы. Для финальной продуктовой приемки рекомендуется дополнительная сессия с пользователем экранного диктора.

## 2. Среда

Обязательная конфигурация:

- Windows Narrator и Microsoft Edge либо Chrome актуальной версии;
- Storybook `http://127.0.0.1:3000`;
- масштаб браузера 100%, затем отдельная повторная проверка ключевых сценариев при 200%;
- русский язык Storybook и русский голос экранного диктора;
- управление только клавиатурой: `Tab`, `Shift+Tab`, стрелки, `Enter`, `Space`, `Escape`.

Дополнительная конфигурация: NVDA с Firefox или Chrome. Если Firefox runtime недоступен, это фиксируется как ограничение среды, а не как успешная проверка.

Перед началом открыть каждую историю напрямую по маршруту `/iframe.html?id=<story-id>&viewMode=story`, чтобы панель Storybook не попадала в порядок фокуса.

## 3. Правило результата

Сценарий получает `passed`, только если одновременно выполнены условия:

- элемент объявлен понятным русским именем и правильным типом;
- состояние `disabled`, `required`, `invalid`, `expanded`, `selected` или `checked` объявляется, когда применимо;
- порядок фокуса соответствует визуальному и логическому порядку;
- overlay не выпускает фокус в фоновый интерфейс и возвращает его на триггер;
- динамическое сообщение произносится один раз и в нужный момент;
- пользователь может завершить сценарий без мыши.

Непонятное имя, потеря фокуса, недоступное действие или отсутствующее критичное сообщение считаются дефектом. Косметическая многословность фиксируется отдельно с фактической транскрипцией.

## 4. Матрица сценариев

| ID | Story ID | Действия | Ожидаемое объявление и результат |
| --- | --- | --- | --- |
| SR-01 | `tend-ui-primitives-button--primary` | Перейти `Tab`, активировать `Enter`, затем `Space`. | Объявляется русское имя и роль кнопки; обе клавиши активируют одно действие; фокус остается предсказуемым. |
| SR-02 | `tend-ui-primitives-input--default` | Перейти к полю, ввести текст, очистить доступной кнопкой. | Объявляются label/имя и роль поля; ввод не сопровождается лишними сообщениями; кнопка очистки имеет понятное имя. |
| SR-03 | `tend-ui-form-form--rules` | Перейти по полям, отправить пустую форму, исправить ошибку. | Required/invalid и текст ошибки связаны с нужным полем; ошибка произносится после submit и не повторяется бесконечно. |
| SR-04 | `tend-ui-main-primitives-select--medium` | Открыть `Enter`, пройти варианты стрелками, выбрать, снова открыть и закрыть. | Combobox сообщает collapsed/expanded; активный вариант и выбранное значение объявляются; закрытие возвращает фокус на combobox. |
| SR-05 | `tend-ui-main-primitives-modal--keyboard-accessibility` | Открыть окно, пройти все элементы `Tab`/`Shift+Tab`, закрыть `Escape`. | Объявляются dialog, заголовок и описание; фокус ограничен окном; после закрытия возвращается на кнопку открытия. |
| SR-06 | `tend-ui-filters-filters--default` | Открыть фильтры, изменить поле, применить или закрыть. | Объявляются dialog и заголовок фильтрации; labels связаны с контролами; фокус не уходит в фон и возвращается на триггер. |
| SR-07 | `tend-ui-table-table--keyboard-accessibility` | Перейти к таблице, пройти заголовки и строки, открыть фильтры. | Объявляются table/region, заголовки и содержимое ячеек; назначение кнопок заголовка понятно; горизонтальная прокрутка не скрывает клавиатурный доступ. |
| SR-08 | `tend-ui-tree-tree--default` | Перейти к дереву, раскрыть узел стрелкой/`Enter`, перейти между узлами. | Объявляются tree/treeitem, уровень, expanded/collapsed и имя узла; переход следует структуре, скрытые узлы не попадают в чтение. |
| SR-09 | `tend-ui-upload-uploadarea--default` | Перейти к зоне загрузки, активировать клавиатурой, отменить системный выбор файла. | Объявляются назначение и доступное действие; активация работает без мыши; отмена возвращает фокус в интерфейс. |
| SR-10 | `tend-ui-main-primitives-toast--success` | Активировать показ уведомления и дождаться завершения. | Успешное сообщение произносится один раз через live region; фокус не перемещается в toast. |
| SR-11 | `tend-ui-main-components-asyncselect--api-retry` | Дождаться ошибки, активировать повтор, выбрать вариант. | Ошибка и восстановление объявляются своевременно; combobox сохраняет понятное состояние; выбранное значение произносится. |
| SR-12 | `tend-ui-header-hooks-usesupportmodal--default` | Перейти к кнопке помощи, открыть и закрыть окно. | Кнопка имеет русское имя; dialog объявляет заголовок; закрытие возвращает фокус на исходный триггер. |

## 5. Сквозные проверки

Для SR-03, SR-04, SR-05, SR-07, SR-08 и SR-11 дополнительно проверить:

1. `Shift+Tab` не меняет логический порядок на противоположный визуальному.
2. Повторное открытие не создает дублированных объявлений или скрытых фокусируемых копий.
3. После обновления истории фокус начинает путь с предсказуемого места.
4. При масштабе 200% управление и объявления остаются теми же.
5. В режиме высокой контрастности состояние фокуса различимо не только цветом.

## 6. Форма доказательства

Для каждого сценария сохранить:

```text
Дата и исполнитель:
ОС, браузер и версия:
Экранный диктор и версия:
Story ID:
Последовательность клавиш:
Фактическая транскрипция:
Ожидаемый результат:
Статус: passed / failed / environment-blocked
Severity при failed: critical / serious / moderate / minor
Ссылка на issue или исправление:
```

Итоговая приемка требует 12/12 `passed` либо отдельного документированного решения по каждому `environment-blocked`. Автоматические отчеты нельзя использовать вместо фактической транскрипции.
