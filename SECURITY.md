# Security Policy

## Поддерживаемая версия

До первого публичного релиза поддерживается текущая версия исходного репозитория и пакетная линия `4.82.x`. Старые архивные состояния не получают отдельные исправления безопасности.

## Как сообщить об уязвимости

Не публикуйте сведения об уязвимости, exploit, токены, ключи или персональные данные в открытом issue.

После размещения репозитория на GitHub используйте **Security -> Advisories -> New draft security advisory**, если эта функция включена владельцем. До настройки remote и GitHub Security Advisories передайте описание владельцу репозитория по согласованному приватному каналу.

В сообщении укажите:

- затронутый пакет, версию и публичный import path;
- минимальный сценарий воспроизведения;
- ожидаемое и фактическое поведение;
- оценку влияния;
- возможный вариант исправления, если он известен.

## Границы проверки

- Автоматизированный dependency audit использует только публичный npm registry.
- Закрытые корпоративные системы и учетные данные не являются допустимыми источниками или целями проверки.
- CI не публикует пакеты, не использует publish-токены и работает с `contents: read`.
- Актуальные SBOM, license inventory и security gate формируются командами `npm run security:r08:audit` и `npm run quality:r08` из `app/`.

Срок ответа и публичная политика раскрытия будут определены владельцем после выбора режима репозитория и канала поддержки.
